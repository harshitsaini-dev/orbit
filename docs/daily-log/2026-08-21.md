  one Render free service covers API + WS + cron.
- AES-256-GCM helpers for token-at-rest encryption plus a `redact()` log filter.
- Frontend: Vite + React + PWA plugin, Claymorphism token system, three-way theming

## Decisions

- ADR 0001: aggregate-only — Orbit never persists file bytes.
- ADR 0002: libSQL/Turso over a hosted Postgres, so local and hosted modes share one driver.
- ADR 0003: one Node process for API + WebSocket + cron, to fit a single free Render service.

## Session 2 — Phase 1 (auth)

### Built

- Published the repository: <https://github.com/harshitsaini-dev/orbit> (public, MIT).
- Passwordless email OTP. Codes are 6 digits from `randomInt`, stored as salted **scrypt**
  hashes — scrypt rather than argon2 specifically to avoid a native build step on the free
  tier (ADR 0004). 5-minute expiry, 5-attempt cap, 60-second resend cooldown, consumed on
  first success so a code can never be replayed.
- Sessions: 32 random bytes, stored only as a SHA-256 fingerprint, in an `httpOnly` +
  `sameSite=strict` cookie. Logout deletes the row rather than only clearing the cookie.
- Sign-in doubles as registration; the first account ever created becomes `superadmin`, so a
  fresh deployment is never left without an administrator.
- Resend mailer with a console transport when no API key is set, plus a gated in-memory outbox
  so the E2E suite can drive the real flow without a mailbox (ADR 0005).
- `attachUser` / `requireAuth` / `requireRole`. Admin routes answer 404 rather than 403 so the
  admin surface is not confirmed to a non-admin; the frontend mirrors that.
- Frontend: two-step login screen (email → code) with a live resend cooldown, `AuthProvider`,
  route protection that remembers where the user was headed, and a sign-out control.

### Tested

- 55 unit tests pass. The auth suite asserts the security properties directly rather than just
  the happy path: identical responses for known and unknown addresses, one indistinguishable
  error for every verify failure, no code in any response body, no plaintext code in the
  database, replay rejected, attempt lockout that survives a later correct code, and a
  logged-out cookie failing on reuse.
- The rate limiter got its own test with a deliberately low limit, so the rest of the suite can
  run with headroom without leaving the limiter uncovered.
- 21 Playwright tests across desktop/tablet/mobile, three consecutive clean runs.

### Fixed along the way

Four real defects surfaced while getting the suite green, each worth recording:

1. **Relative `file:./orbit-e2e.db` resolved to two different files** — drizzle-kit ran from
   `packages/db`, the server from `apps/server`. Now an absolute `file://` URL, computed once.
2. **Playwright silently reused a stale dev server.** `reuseExistingServer` adopted a server
   started without the suite's environment, so requests hit the default rate limit and the
   429's non-JSON body surfaced as a generic "Request failed". The E2E stack now runs on its
   own ports (8788/5174) with reuse disabled (ADR 0006).
3. **A test read the OTP before the send request had settled.** `lastCode()` now polls, and the
   test waits for the code step first.
4. **SQLite defaulted to rollback-journal mode**, which serialises every write behind an
   exclusive lock. Local file databases now enable WAL and a busy timeout.

### Decisions

- ADR 0004: passwordless OTP hashed with scrypt.
- ADR 0005: a gated dev outbox instead of a mailbox in tests.
- ADR 0006: dedicated E2E ports, no server reuse, absolute database URL.

## Session 3 — hero polish and owner runbook

### Built

- Rewrote the three.js hero. The first pass was a flat icosahedron with hairline rings; it did
  not match the soft-clay language of the rest of the UI. Now:
  - ACES filmic tone mapping and correct colour space, so the bright hub rolls off instead of
    clipping to flat white.
  - Matte `MeshPhysicalMaterial` bodies with sheen and a light clearcoat - soft and chunky, no
    glass or chrome.
  - Three-point lighting: hemisphere fill for the shadowless base, a shadow-casting key for
    form, and an accent-coloured rim to separate the silhouette from the card behind it.
  - A back-face atmosphere shell and an additive glow sprite around the hub, which reads as
    bloom without the cost of a postprocessing pass.
  - Five orbiters on independently tilted rings, each tinted by rotating the accent hue, with a
    faint trailing companion to suggest motion.
  - A dust field, a soft contact shadow, a slow "breath" on the hub, and pointer parallax that
    eases back on its own.
  - Light and dark get different exposure, light colours, and opacities.
- The scene now rebuilds when the accent or theme changes, so the accent picker restains the
  whole hero instead of leaving it on the colour it happened to mount with.
- `npm run test:e2e` is now genuinely watchable: headed, one browser, one worker, and 700 ms of
  slow motion driven by `ORBIT_SLOWMO`. `npm run test:e2e:all` keeps the fast full matrix.
- Added `docs/05-owner-setup.md` - click-by-click instructions for every account and API key the
  project needs, starting with the Google OAuth client that unblocks Phase 2.

### Tested

- 55 unit tests, clean typecheck, clean build.
- 21 Playwright tests headless across three viewports; 7 headed in slow motion.

## Session 4 — branding, full provider coverage, developer platform design

### Built

- **Brand mark.** A Saturn-style favicon read as a ringed planet rather than as Orbit, so it was
  redrawn as a glowing hub with bodies in orbit around it - the same idea as the three.js hero.
  Two intermediate versions were discarded: equal-sized crossing rings read as an atom, and a
  semi-transparent halo let the orbits show through the hub. The final mark has one bold orbit
  that passes behind the hub at the top and in front at the bottom, clipped to the hub's own disc
  so the two copies never stack into a visible seam.
- `scripts/generate-brand-assets.mjs` rasterises the mark into the PWA icon set, an Apple touch
  icon, a maskable icon with the required safe-zone inset, and a 1200x630 link-preview card. It
  drives the Chromium that Playwright already installs, so no native image dependency was added.
  The card inlines the same `favicon.svg`, which means the two can never drift apart.
- Open Graph and Twitter card metadata, with absolute image URLs - crawlers do not resolve
  relative ones.
- **Full provider coverage.** Nine adapters and a fourteen-entry catalogue (ADR 0007). The
  catalogue is deliberately a separate concept from the adapter registry: Amazon S3, Cloudflare
  R2, Supabase Storage, DigitalOcean Spaces and Backblaze B2 all speak the same API, so they
  share one adapter and differ only in an endpoint template and field list. Adding another
  S3-compatible service is now a data change, not new code.
- Google Cloud Storage, Azure Blob Storage and Bunny Storage got their own adapters, since none
  of the three speaks S3.
- Two capability flags added for object stores - `nativeFolders` and `reportsQuota` - so the UI
  can adapt rather than render an empty quota bar for a bucket.
- `GET /api/catalogue` serves the catalogue with adapter capabilities attached, and the Home page
  renders it grouped.
- **Developer platform designed** in `docs/06-developer-platform.md` and added to the roadmap as
  Phase 11: a versioned `/v1` API, personal access tokens, OAuth 2.0 with PKCE and per-account
  consent, scoped permissions, webhooks with signed deliveries, a Developer tab, and an API docs
  tab generated from the Zod schemas the routes already validate with. Placeholder routes for
  `/developer` and `/developer/docs` are in the nav so the shape is visible.
- Playwright now runs **headed by default** locally, at 250 ms slow motion, per the user's
  preference; CI is the only place it goes headless.

### Not built, and why

iCloud Drive and Proton Drive were both requested and neither can be supported. Apple publishes
no API for third-party access to a user's iCloud Drive; Proton publishes no public Drive API at
all. Rather than omit them or ship stubs that could never work, both are listed in
`UNAVAILABLE_PROVIDERS` with the reason and what would unblock them, and served from
`/api/catalogue` so the connect dialog can explain itself.

### Tested

- 80 unit tests. The new catalogue suite checks the two registries cannot drift: every entry
  points at a real adapter, every adapter is reachable from an entry, every `{placeholder}` in an
  endpoint template is actually collected from the user, and every secret field is marked secret.
- A server test asserts `/api/catalogue` never carries credential *values*, only field
  definitions.
- 21 Playwright tests across three viewports, headed.

## Landing page, media viewers, and account identity

### Built

- A proper landing page: what Orbit is, six cards covering the properties that
  distinguish it, three steps to a working workspace, the full provider
  catalogue, and what is not supported with the reason. The call to action is
  "Create your workspace" in hosted mode - a visitor with no account is being
  asked to register, not to connect something they do not have.
- Theme and accent controls on the landing and login pages. Appearance lived in
  the account menu, so someone arriving on a bright page at night had no way to
  turn it down before signing in.
- An install button that appears only once the browser fires
  `beforeinstallprompt` and hides once installed. The service worker now also
  registers in development, without which the button could never be tried
  locally - but not under Playwright, where it held the load event open long
  enough to time the suite out.
- Orbit's own audio and video player, and a fit-then-zoom image viewer.
- A thumbnail queue. Scrolling a large folder had been firing a request per
  tile, saturating the browser's connections to the origin and starving
  everything else; requests are now capped and cancelled on scroll-away.

### Fixed

- Reconnecting an account duplicated it. Accounts now carry the provider's own
  id and authorising one Orbit already holds refreshes that connection in place.
  A grant expiring is routine - under a Testing-mode OAuth client it happens
  every seven days - so this was a matter of when, not whether. Existing
  connections were backfilled from the address they were already labelled with.
- The account menu now says why local mode has no sign-out, instead of simply
  omitting it and reading as a missing feature.

### Verified

- 256 unit tests, 117 Playwright tests across three viewports, headed.
- The reconnect path has its own tests: same account refreshes in place, two
  different accounts stay apart, and connections without a provider identity
  never merge.
